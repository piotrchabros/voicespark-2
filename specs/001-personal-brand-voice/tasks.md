# Tasks: Personal Brand Voice

**Input**: Design documents from `/specs/001-personal-brand-voice/`

**Prerequisites**: plan.md (required), spec.md (required for user stories), research.md, data-model.md, quickstart.md, contracts/ (`http-api.md`, `jobs.md`, `filter-categories.md`, `prompt-template-variables.md`, `supermemory.md`)

**Tests**: The spec does not request TDD globally. Test tasks are included only where the plan's gates require them: the sensitive-content corpus and detector unit tests before detector code (gate G4; SC-004, SC-005), the admin content-isolation suite (SC-010; FR-045, FR-060), the Supermemory adapter contract test, the pause/resume dedup test (SC-011), the first-import filter gate test (SC-014) and Playwright e2e per quickstart scenario in the Polish phase. Every test task precedes the implementation it covers.

**Organization**: Tasks are grouped by user story so each story can be implemented and tested independently. Enum literals, table names, route paths, queue names and env var names are quoted exactly from data-model.md and the contracts.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: Which user story this task belongs to (US1..US8); required in story phases, absent in Setup, Foundational and Polish
- Every task names the exact file path(s) it creates or edits

## Path Conventions

Monorepo per plan.md: `apps/web` (`@voicespark/web`, Next.js App Router, user app + `/admin`), `apps/worker` (`@voicespark/worker`, BullMQ processors), `packages/db` (`@voicespark/db`), `packages/core` (`@voicespark/core`), `packages/filters` (`@voicespark/filters`), `packages/integrations` (`@voicespark/integrations`), `docker/`, root config files.

## Phase 2: Foundational (Blocking Prerequisites)

**Purpose**: Shared schema, crypto, auth base, guards, queues, external adapters, the fail-closed filter pipeline (test-first), audit, notifications, settings, deletion core, seed and the first-admin CLI. No user story work can begin until this phase is complete.

**Decision on the filter pipeline**: the core engine of `@voicespark/filters` (catalog, detectors, credential-delivery stage, classifier, rules matcher, fail-closed `inspect()`) is built here, test-first, so US2's import pipeline can never write to Supermemory without it. US3 then adds the user-facing checklist, preferences API, exclusion rules, summaries, reports and retroscans. See Dependencies.

## Notes

- `[P]` tasks touch different files and have no dependency on an incomplete task; tasks without `[P]` either share a file with a neighbour or depend on the previous task.
- Every schema task quotes the data-model.md constraints it must enforce; copy them into column definitions, check constraints and partial unique indexes rather than only into comments.
- Migrations are one per phase that adds tables (`0000` Foundational, `0001` US1, `0002` US2, `0003` US3, `0004` US4, `0005` US5, `0006` US8); US6 and US7 add no tables.

- Test files follow `*.integration.test.ts` for compose-backed suites so `pnpm test` stays fast and `pnpm test:integration` runs them.
- Never log `InspectionInput`, matched values, bodies or subjects; `InspectionResult` carries counts only. The `SafeLogFields`-typed logger and the pino redaction in T026 enforce this mechanically (a violation fails `pnpm typecheck`).
- Commit after each task or logical group; stop at each checkpoint to validate the story independently.
