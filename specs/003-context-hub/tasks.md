# Tasks: Context Hub

**Input**: Design documents from `/specs/003-context-hub/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, quickstart.md, contracts/ (`http-api.md`, `jobs.md`, `hub-extraction.md`, `memory-store-hub.md`, `filter-hub-mode.md`, `hub-search.md`)

**Tests**: Included. Constitution Principle IV (Test-First Filtering) and plan.md "Testing" require the hub-mode corpus and the tests for `inspectForHubExtraction`, `validateContactValue`, `inspectSegments` and `buildHubDocument` to be written first and to fail first. Every story phase lists its failing tests (unit, integration, contract, admin-isolation, e2e) before the code they cover. quickstart.md section 4 lists what each gate command must cover.

**Organization**: Tasks are grouped by user story (spec.md US1–US8) in the order of plan.md "Delivery increments". US8 is split into two phases: "US8 (account)" ships with the MVP and "US8 (mailbox)" follows the email increment. Both carry the `[US8]` label.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: US1–US8 from spec.md; present only in story phases
- Paths are relative to the repository root (`/root/voicespark-2`); every task names the exact file(s) it creates or edits
- Enum literals, table names, routes, job names, env names and limits are quoted exactly from data-model.md and the contracts

## Notes

- `[P]` tasks touch different files and have no dependency on an incomplete task; tasks without `[P]` share a file with a neighbour or depend on the previous task
- Shared host: never run `pkill`, `killall` or any kill by name; the e2e harness stops its own worker by process group. Never point any test at the production memory store (`supermemory.voicespark.ai`) or `127.0.0.1:6770`; tests use `InMemoryMemoryStore`, the fake v3 server or the memory bridge on 4599. E2E runs are serialised with `flock /tmp/voicespark-e2e.lock` on web port 3110 (3100 is taken). Ports: Postgres 55432, Redis 56379, GreenMail 3025/3993
- Test-first: the hub corpus (T021) and the filter tests (T022–T026) must fail before T027/T028; every story's test tasks precede its implementation tasks
- No message body is ever stored, logged or placed in a job payload, `hub_llm_call` row or audit entry; typed loggers accept ids, counts and codes only
- The extraction prompt (`HUB_EXTRACTION_PROMPT_V1`) is a code constant and not admin-editable; SC-004 to SC-006 are claimed only from the held-out eval line
- `apps/web/proxy.ts` is the Next 16 request hook and its matcher excludes `/api/**`; the body-limit key is `experimental.proxyClientMaxBodySize` (T004) and the upload route checks `content-length` itself (T066)
- The single `hub` Worker runs with concurrency 12 (the sum of the per-job limits, set in the `concurrency` map of `apps/worker/src/index.ts`); a per-job-name semaphore built from `HUB_CONCURRENCY` enforces 4/1/4/2/1 (T063)
- Commit after each task or logical group; stop at each checkpoint to validate the story independently
